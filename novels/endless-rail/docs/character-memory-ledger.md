- 第1～66章仓库旧正文仍可能与平台稿漂移，**不得直接在旧文件上做历史正文小修并假装已经同步**。
- 本轮人物扫描因此以完整 `author-editor` 导出直接审计第1～70章，并以仓库第71章补足最新状态；仓库旧正文只用于定位文件结构，不作为历史事实源。
- 下文“最大连续缺席”默认按**相邻两次具名出现之间没有出现该名字的完整章节数**计算；若中间只是回想/转述而非本人有效出场，会另外标注“有效空窗”。

## 1. 读者记忆硬规则

### 1.1 角色重新出现时，不只检查“设定上是否存在”

写到一个已有名字前，必须同时回答：

1. 他第一次在哪一章真正进入读者视野？
2. 第一次具名是否早于人物实际入场？如果是，先修连续性泄漏，不能靠后文补介绍掩盖。
3. 当时读者靠什么记住他：关系、职业、动作、冲突，还是只有一个名字？
4. 最近一次真正参与场景是哪一章？
5. 中间是否连续多个章节只在账本里存在、正文没有有效动作？
6. 本次重登场如果只写名字，普通追更读者能否在一句内恢复身份？

如果第6项不能确定，正文第一次重新出现时必须加入一个**自然身份锚点**。

身份锚点应嵌在动作里，例如：

- `负责外勤的孙海峰已经把接驳车停到侧线。`
- `当初留在零号研究所的冯立又发来一条加密消息。`
- `白栎医疗负责人宋雨眠在固定通信窗口接了进来。`

禁止写成人物卡：`孙海峰，外勤驾驶员，曾于第9章加入。`

### 1.2 触发重锚的默认条件

满足任一项，新场景优先补身份：

- 连续 **8章以上** 没有有效出场；
- 虽然提过名字，但连续 **5章以上** 没有动作、对话或关键决定；
- 首次出场发生在高压大章、群体救援、多人同时入场或系统提示密集段；
- 角色从“临时乘员/路人”升级为长期核心成员，但中间缺少独立人物场景；
- 同一阶段存在姓名相近、职业相近或功能相近的人物；
- 角色跨卷、跨站点、跨长篇章重新出现。

数字是警戒线，不是机械模板。即使只隔三章，只要角色记忆弱，也可以重锚。

### 1.3 首次具名顺序也属于连续性

本轮发现的孙海峰问题不是普通“读者忘了”：平台真实稿第6～8章已经使用他的名字和驾驶动作，但第9章才把他作为故障列车求援者正式接入归途站。

因此以后只要移动、重写或延后人物加入章节，发布前必须反向搜索该角色在此前所有章节的名字：

> **第一次具名不得早于人物在剧情中的实际入场。**

一旦存在这种泄漏，优先修掉提前出现的旧残留；不能用“后面再介绍一次”代替修复。

### 1.4 不要反复介绍熟人

周野、周建国等高频核心角色不应每次重新解释身份。重锚只在读者确实可能遗忘时使用，而且一处足够。后续同章继续直接叫名字。

## 3. 必须修：已确认的正文问题

### P0-A：孙海峰不是单纯“读者忘了”，而是第6～8章存在提前漏名

- 但第9章才把【孙海峰】作为寒潮中故障列车的求援者正式接入，随后他带着妹妹孙晓雨上车。

这四章不能同时成立。读者问“孙海峰哪里来的”有真实文本依据，也会自然产生“是不是拼接/搬运”的怀疑。

**处理要求：**

1. 第9章正式进入链保持不动；
2. 第11章“以前做过货车司机”、潜在岗位“外勤驾驶员”保持不动；
3. 第13章“以后外勤车你管”的正式岗位兑现保持不动；
4. 必须回修第6～8章中提前出现的孙海峰姓名/驾驶归属，使他在第9章之前不作为已在车上的成员存在；
5. 不能靠第9章再加人物简介掩盖第6～8章的时间线错误。

当前第6～8章平台真实正文尚未以安全版本恢复进仓库，因此**本轮不直接改仓库旧 `chapters-006-009.md`**。应先以最新平台稿回修，再重新 `author-editor` 导出并恢复，避免把旧仓库版本反向写回平台。
