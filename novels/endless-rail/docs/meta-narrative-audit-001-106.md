# 第1～106章元叙事泄露重审计报告

> 审计日期：2026-08-29
>
> 审计范围：`novels/endless-rail/chapters/` 下第1～106章全部正式正文。
>
> 审计性质：此前第87～106章及“第1～106章全量项目审计通过”结论，在发现正文存在章节号/写作层泄露后失效。本报告是该维度的重新验收结果。

## 一、问题定义

小说正文不得感知自己位于小说中。

除 Markdown 章节标题外，正文禁止出现：

- `第XX章`、`上一章`、`下一章`、`本章`；
- `上一卷`、`下一卷`、`本卷`；
- `正文`、`剧情`、`作者`、`读者`、`章节`、`排章` 等写作层词；
- 人物讨论“晚一章”“排章”等写作安排；
- 旁白以“是否展开/是否写完整过程”解释作者的叙事取舍。

前文事实必须改用世界内锚点：任务编号、具体事故、前一天、上一次、前一批、某次检测/运输/交易等。

永久规则见：`shared/META_NARRATIVE_RULES.md`。

## 二、首次全书扫描

新增独立扫描器：

`shared/tools/meta_narrative_guard.py`

并对第1～106章全部运行。

第一轮机器结果为 `hard=26, warn=6`。人工逐条复核后发现其中包含少量正则误报，例如：

- “公路上卷过来”里的世界内普通词组；
- 第59章对白中的实体“这一卷”；
- P-01机械结构“再次展开”。

因此先收紧扫描规则，再认定真实问题，避免为了过检查误改正常中文。

## 三、真实修复范围

最终共修改 **18个章节、27处原句**。

涉及章节：

`23、72、87、88、89、90、91、92、93、94、96、97、98、99、101、103、104、105`。

其中包括：

- 24处明确的章节号、卷号、正文/剧情等第四面墙泄露；
- 3处明确带有作者叙事取舍痕迹的高风险表达，一并世界内化。

典型修复：

- `第99章那一班把暖桥第二台生活水泵送回去以后……`
  → `暖桥第二台生活水泵上次送回去以后……`
- `他调出第十二章铺设临时钢轨桥时留下的结构记录。`
  → `他调出此前铺设临时钢轨桥时留下的结构记录。`
- `第31章时，旧港发来的第一条正式消息……`
  → `最早收到旧港那条正式消息时……`
- `上一卷北岬结算送来的八米灯条……`
  → `N-3-4结算时北岬送来的八米灯条……`
- `维修没有因此变成另一条长剧情。`
  → `维修范围到这里就收住了。`

所有修复均为指定章节中的精确替换，没有批量模糊改写正文。

## 四、修复后全书复核

修复完成后，GitHub Actions 对第1～106章再次逐文件执行永久扫描。

结果：

`TOTAL hard=0 warn=0`

即：

- 第1～106章章节号/相对章节引用泄露：0；
- 卷号结构泄露：0；
- `正文/剧情/作者/读者/章节/排章` 等写作层泄露：0；
- 当前扫描器定义的作者式展开/写作过程警告：0。

本次重审在元叙事隔离维度通过。

## 五、永久门禁

已新增：

- `shared/META_NARRATIVE_RULES.md`：零容忍规则与世界内替换原则；
- `shared/tools/meta_narrative_guard.py`：独立扫描器；
- `.github/workflows/meta-narrative-guard.yml`：对《无尽轨道》正式章节自动执行扫描。

以后正文只要重新出现上述硬泄露，CI 会直接失败。

以后任何“全量审计通过”若没有包含元叙事隔离检查，不得再称为全量审计。若已通过的正文后来发现此类泄露，旧结论自动失效并必须重新审计。
