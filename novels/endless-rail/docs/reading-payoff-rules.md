# 阅读兑现规则

> 状态：**本书专属权威补充规则**。与 `docs/writing-rules.md`、`shared/RULES.md`、`shared/PROSE_RULES.md` 一起约束后续正文。
>
> 来源：2026-08-27 番茄真实章节数据复盘。平台明确提示第32章读完率下滑、第44章跟读率偏低，约第48章附近存在孤立深坑。该证据只用于修正“过程长期占正文、现实收益总延后一章”的问题，不用于因单日推荐流量波动大面积重写全文。

## 1. 每章必须检查阅读兑现速度

技术验证、维修、交易、成本核算、制度建立连续出现时，交付前强制回答：

> **这一章结束时，读者实际拿到了什么新的东西？**

可以是：

- 新资源；
- 新设施；
- 新路线；
- 新权限；
- 新交易结果；
- 人物关系发生实际变化；
- 一次明确失败迫使下一步选择改变；
- 风险真实升高或降低；
- 一个足以承接下一章的强悬念。

答案必须来自正文已经发生的事件。

“数据记录更完整”“又测试了一轮”“成本算清了”“流程准备完毕”可以是剧情过程，但单独占满一章时，不算充分兑现。

## 2. 过程占满一章时的处理顺序

如果一章主要由同类流程组成，按以下顺序检查：

1. **删重复**：同一结论已经通过一个样件、一次对白或一组数字成立，后续相同过程用摘要或动作压缩。
2. **保留决策点**：技术数字只保留会改变“继续 / 停止 / 降级 / 交易 / 路线选择”的部分。
3. **前移现实收益**：下一章开头已经存在一个自然成果时，优先考虑把其中一个可见收益前移，而不是让本章只负责准备。
4. **必要时合并**：若压缩后本章仍没有独立变化，检查是否应与相邻章节合并，而不是补新的无关事件。

不得为了通过此规则硬塞奖励、系统升级或无来源爽点。

## 3. 强钩子不能被整章准备流程拖住

上一章已经明确许诺“出发、进入、揭晓、交易结果、危险兑现”时，下一章前段必须尽快开始偿还这个期待。

允许存在真实门槛，例如能源、安全检查、路线许可和专业准备。

但准备内容要满足至少一项：

- 它直接决定能否完成上章承诺；
- 它会在本章产生可见结果；
- 它将在紧接着的任务中立即使用。

普通补给清单、重复设备检查和送别流程应压缩。

强悬念被证明是虚惊时，也要迅速把虚惊转化为更大的有效信息，避免“吊高以后只剩一个小答案”。

## 4. 技术细节的正文准入条件

同类技术流程连续出现时，一项细节至少要改变以下之一，才值得展开：

- 是否继续处理；
- 是否停止；
- 成本多少；
- 资源是否可复用；
- 专业人员判断；
- 路线/权限；
- 交易条件；
- 风险等级。

不能改变决策的重复清洗量、重复测试轮次、重复设备占用，优先进入货单、成本页摘要或一句场景动作。

权威账本可以比小说正文更完整。

## 5. 每章不强制“爽点”，但必须有变化

本规则不要求每章发财、升级或打脸。

安静章、生活章、失败章都允许。

最低要求是章节结束后，读者能明确感觉到至少有一项东西和开头不同：

- 人；
- 物；
- 路；
- 权；
- 关系；
- 风险；
- 选择；
- 已知事实。

如果只能回答“为下一章准备好了”，优先压缩。

## 6. 数据使用边界

- 单日阅读人数、书城流量的涨跌先区分推荐放量与回收，不直接等价于正文质量。
- 优先处理**孤立的章节级读完率 / 跟读率断点**，并对照上下章查“承诺—过程—兑现”是否错位。
- 一次异常只支持小范围精准整改，不支持无证据地重写整卷。
- 修订后继续保留事实连续性、路线权限、专业边界和成本逻辑；不能为了留存把已成立的世界规则删掉。
- 后续有新的平台章节数据时，先记录现象，再查正文因果，禁止先按印象改稿。
