## 二、硬约束

### 更新节奏

- 9月16日至9月30日采用稳定公开档：**3章/日**。
- 不按5章/日继续硬冲到月底，避免把第四卷事故、多核心合作和第五卷开场压成流水账。
- 单章目标：2800～3500字；硬上限3800字；关键章确实需要连续高潮时再临时放宽。
- 每章只完成一个主目标，最多一个次级回报。
- 每天3章必须形成一个小闭环：提出现场问题 → 产生专业/路线/权限阻碍 → 得到可见结果或明确失败。

### 内容边界

- 医疗核心强在消毒、分诊、医疗设备维护和大量伤员处理，不是万能治愈。
- 防御核心强在屏障、隔离、雾压驻留和危险区停留，不写成打怪战斗列车。
- 制造核心仍强在标准件批量生产，不被强行削弱。
- 归途站强在兼容、接口、接力、多站协同和授权整合，不能吞并其他核心能力。
- 多核心合作必须有各方授权；不能因为周野是主角就自动接管别人的系统。
- 章末优先落在设备状态、路线条件、工单、照片、车内动作或下一项具体任务，不写抽象总结升华。

## 五、执行检查

每3章写完后检查一次：

1. 今日3章是否有一个完整小闭环；
2. 每章是否只有一个主问题；
3. 是否有至少一个可见变化：人、物、路、权、风险、关系或已知事实；
4. 是否让MED、DEF、F-02、归途站各自保持能力边界；
5. 是否避免“项目周报式旁白”和章末总结升华；
6. 是否有具体场景承接下一章，而不是作者解释意义。

平台进入前检查：

- 正文文件存在且编号连续；
- 章节标题与排期一致，或在正文完成后同步更新本文件；
- 字数符合2800～3500常规目标，超3800必须拆章或说明原因；
- Novel Gate / Meta hard 均为0；
- 连续性、人物记忆、能力增长账本完成更新；
- `platform-sync` 只读核对远端章节编号、标题、重复项和已排日期后，再执行任何创建或重排。
