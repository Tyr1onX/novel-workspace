# 小说正文元叙事隔离规则 V1

> 适用范围：所有 `novels/*/chapters/**/*.md` 的正式正文。
> 性质：硬闸门，零容忍。

## 核心原则

小说中的人物、叙述者和世界只能知道**世界内发生过什么**，不能知道自己位于第几章、第几卷，也不能感知作者的写作安排。

Markdown 章节标题可以写 `# 第101章 ...`；标题以下的正文不得以小说结构作为事实锚点。

## 正文绝对禁止

包括但不限于：

- `第99章那一班`、`第31章时`、`第十二章铺桥时`；
- `上一章`、`下一章`、`本章`、`上一卷`、`下一卷`；
- `正文里不需要再……`；
- `进入某段剧情`、`另一条长剧情`、`剧情线`；
- `作者`、`读者`、`章节`、`排章`；
- `电的我晚一章`、`你还给自己排章？`；
- 人物对白中直接讨论小说章节、写作安排，同样禁止。

## 正确的世界内锚点

需要回指前文时，改用人物真实能够知道的时间、任务、物件或事件：

- `第89章那批低温柴油` → `前一批低温柴油`；
- `第71章东联络桥那次` → `此前东联络桥那次检测`；
- `第102章的跨站对象索引` → `刚启用的跨站对象索引`；
- `上一卷北岬结算送来的灯条` → `N-3-4结算时北岬送来的灯条`；
- `第99章那一班` → `上次把水泵送回暖桥以后`。

优先使用：

- 任务编号；
- 站点和线路名称；
- 前一天 / 上一次 / 前一批 / 前几班；
- 某次事故、检测、运输或交易；
- 人物自己的记录、日志、货单、工单。

## 写作流程词也不得漏进正文

即使没有直接写章节号，下面这类句子仍应视为泄露：

- `正文里不需要再守着……`；
- `他已经很久没进入这段剧情`；
- `维修没有因此变成另一条长剧情`；
- `别再一只一只写成长试验`；
- `这一只没有继续展开的必要`（当“展开”指作者是否展开描写时）；
- `没有再复制某某的完整过程`（当句子是在说明作者省略描写，而非人物真实工作决策时）。

判断标准只有一个：**这句话如果被世界内人物看到，他们能否把它理解为真实存在的记录、行动或判断？**

不能，就必须改。

## 强制扫描

提交正文前运行：

```bash
python shared/tools/meta_narrative_guard.py novels/<novel>/chapters/volume-*/*.md
```

`HARD` 命中必须清零后才能提交。

`WARN` 也必须人工逐条确认；如果它实际上是在描述作者取舍、叙事省略或写作安排，也必须改。

GitHub Actions 中的 `Meta narrative guard` 会对《无尽轨道》正式章节自动执行该扫描。

## 审计规则

以后任何“全量审计通过”必须明确包含：

1. 元叙事隔离扫描；
2. `HARD=0`；
3. 所有 `WARN` 已人工确认；
4. 章节标题不计入正文命中；
5. 不得只检查新增章节，声称“全书通过”时必须扫描声明范围内的全部正文文件。

如果后来发现正文仍存在章节号、卷号、正文/剧情/作者视角泄露，之前的“全量审计通过”自动失效，必须重新审计。
