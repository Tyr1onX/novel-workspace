# 小说语言去 AI 腔证据整理 V1

> 目的：为 `shared/PROSE_RULES.md` 提供外部方法来源与取舍依据。
> 范围：只讨论小说正文的语言与叙述姿势，不替代 Click / Activation / Retention 等结构研究。

## 1. 为什么需要独立的语言层规则

现有 `shared/RULES.md` 已经能约束爽点、因果、主角所有权和留存，但“故事结构正确”并不自动等于“正文像人写的”。

模型即使拿到正确章节卡，仍容易在句子层自动补齐一套熟悉姿势：先制造一个错误理解，再翻案；连续写出长度接近、骨架相同的句子；动作已经表达情绪后再解释一次；场景结束后替读者总结意义；用抽象情绪词或漂亮比喻把具体事件重新包装。

这些问题不会被章节卡自动消除，因此需要独立的 prose gate。

## 2. 参考仓库

### 2.1 `larashero3-dotcom/lieflat-less-ai-tone`

参考文件：`SKILL.md`、`RESEARCH.md`。

可迁移结论：

- 先读目标作品自己的风格文档；通用去 AI 规则不能覆盖真实作者/作品已经稳定成立的语言习惯。
- “翻案腔”不能只搜固定字符串。`不是 A 而是 B`、`看似 A 实则 B`、`你以为 A 其实 B`、`A 不重要重要的是 B` 都属于同一个叙述动作：先替读者制造一个并不存在的误解，再推翻它抬高结论。
- 相邻句反复使用同一语法骨架、相似长度和相似落点，会出现明显的模板感；应打散其中一处，而不是全篇统一改成短句。
- 不能把“句长不够参差”“段落不够碎”“有排比/比喻”本身当成 AI 证据。文学文本必须保留有意节奏。
- 改稿规则应当定位明确问题，而不是借“去 AI 味”之名把没有问题的句子全部重写。

### 2.2 `YunyueLi/de-ai-prose-zh`

参考文件：`反AI腔自查清单.md`、`prompt模板.md`。

可迁移结论：

- 对中文小说，叙述层的否定—修正句是最高优先级风险；对白中真实纠错可以保留，但不能让叙述者形成口癖。
- 三连排比、三短句连续敲击、重复“没有 A / 没有 B / 没有 C”容易形成生成式节拍。
- 高风险模式还包括：抽象情绪概括、伪深刻破折号、解释式/升华式段尾、`第一次/终于/那一刻` 等高频口头禅、对冲式比喻和过度切碎句子。
- 自查最好可搜索、可定位，机器只负责报命中，最终由人判断是否属于对白、必要强调或作品有意风格。
- 具体动作、物件、身体反应和场景变化应承担情绪；不要先写具体，再跟一句抽象解释把留白收走。

### 2.3 `KKKKhazix/human-writing`

参考文件：`human-writing/SKILL.md`、`references/fiction.md`、`references/revision.md`。

可迁移结论：

- 虚构场景必须由人物目标、动作、选择、关系变化、信息变化或后果托住；换景色和换说法不能充当推进。
- 性格藏在选择里，对白应该在试探、遮掩、说服、拖延、靠近、推开或维护体面，而不是轮流替作者讲主题。
- 细节跟着视角和人物当下压力走；动作已经表达情绪后，不要追加“他犹豫了/他害怕了”式翻译。
- 设定等人物碰到再讲，结尾优先停在后果、动作、关系新位置或旧物新含义，不让叙述者出来总结主题。
- 详细的“清 AI 痕迹”更适合放在初稿之后，初稿阶段应先让人物把事情做出来，避免边写边被黑名单卡成另一种机械文本。

## 3. 共同结论与冲突处理

三个仓库的共同结论不是“越口语越像人”，也不是“越短越像人”。稳定共识是：

1. 让事件、人物和具体材料承担表达，不让作者解释层盖住它们；
2. 降低模型特别爱用的翻案、对称、三拍、同构、升华姿势；
3. 不把某个标点、比喻、排比或长句一刀切禁掉，先判断它是否属于当前作品真实风格；
4. 用可定位扫描帮助发现口癖，但扫描结果必须回到上下文人工判断；
5. 写作和改稿分阶段。第一稿优先人物与事件，第二遍再清生成式姿势。

因此本工作区不采用“所有破折号清零”“所有排比清零”“所有短句合并”这类跨题材绝对禁令。

## 4. 对 Novel Workspace 的落地

长期规则拆成三层：

- `shared/RULES.md`：故事结构、爽点、因果、留存等跨项目规则；
- `shared/PROSE_RULES.md`：小说正文语言与叙述姿势的共享硬闸门；
- 单本小说自己的 README / design / style 文件：作品级语气、视角、人物声音和允许的例外。

执行顺序：

> 项目规则与连续性 → 共享结构规则 → 共享 prose 正向约束 → 写第一稿 → prose 扫描 → 人工复核 → 再交付正文。

扫描工具只能定位，不自动改稿。任何“为了通过扫描”而把正文改成另一套统一模板的做法都视为失败。

## 5. 后续升级条件

只有出现以下证据时才升级 `shared/PROSE_RULES.md`：

- 多个独立外部方法都指出同一稳定模式；
- 我们自己的不同小说正文反复出现同一问题；
- 平台编辑/读者反馈能与具体语言模式对应；
- 新规则能解释旧规则漏掉的问题，并且不会明显误伤正常文学表达。

单次“我觉得这句像 AI”只能进入项目级修改，不能直接升级 shared。
