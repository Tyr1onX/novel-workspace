# 一、《重生：我体内带个台式机》：强样本

## 1. 原生表现与长线

番茄原生页本轮重新核验：

- 已完结；
- 141.0万字；
- 610章；
- 当前约5万人级在读；
- 作品从高考一直写到大学、游戏、公司、芯片、光刻机、智能生态等阶段。

原生来源：

- https://fanqienovel.com/page/7084795093143522343
- https://fanqienovel.com/keyword/7603436360854243355

## 2. 第一章：标题直接把现实计分板钉死

第一章标题就是《我255，想考985》。

主角江成原本是电脑维修工，触电后回到2011年高三，距离高考约60天。前世没考上大学，之后进厂、做销售、学修电脑；重来一次后，他第一次真正明确想“上一次大学”。

公开基线非常具体：三模总分约255，语文约60、数学二十多、英语三五十分、理综基础极差。

因此能力出现前，读者已经知道：

> **60天，255分，想上985。**

这是目前所有样本里最容易复述的一阶计分板之一。

## 3. 前三章：能力很强，但没有把“理解”一起送掉

第一章先发现过目不忘；第二章进一步确认体内还有计算能力。

关键不是能力弱，而是**能力没有自动把数学/理综的理解成本删除**。记得课本、能高速计算，不等于自动会解函数、物理综合题。主角仍需要：

- 借笔记；
- 找题型；
- 看例题；
- 问老师；
- 把“记住”转成“理解和会用”。

因此外挂明显提高学习效率，却没有让现实学习过程完全失去摩擦。

## 4. 前20章：所有胜利都往同一根进度尺累加

目录的推进非常清楚：

- 第1章：255→985目标；
- 第5～6章：小考与第一次公开异常；
- 第8章：相比三模分数接近翻倍；
- 第9章：第四次模拟考；
- 第11章：597分；
- 第12章：高考结束；
- 第16章：水木、京都来抢人；
- 第19～20章：录取通知书/家庭与学校阶段结算。

这里最重要的不是“每章都有爽点”，而是：

> **每一次小爽都能被读者放回同一条人生进度线上。**

255不是一次性噱头，它会被模拟考、597、高考、名校争抢、录取一步步覆盖。

这就是本轮新增变量：

- `cumulative_progress_legibility`：读者是否能把连续胜利理解成同一条可累计的人生进度，而不是一堆相邻但彼此独立的能力展示。

## 5. 约2万字节点

按前期开篇章节长度，约2万字已经处于模拟考/能力公开验证阶段。读者拿到的不是“主角会过目不忘”这个解释，而是：

- 极低基线已建立；
- 学习方式发生变化；
- 分数开始明显上升；
- 老师/家人/同学能够通过考试结果验证变化；
- 985目标仍然没有提前被直接判定完成。

因此仍保留`progression_headroom`：读者知道他已经变强，却还有足够距离继续追。

## 6. 第20章后的stage gate

高考/录取阶段基本结算后，作品才把核心舞台切到：

- 第27章：游戏开发；
- 第32章：游戏上架；
- 第41章：科技梦想/工作室；
- 第46～47章：公司合作、1300万元报价；
- 后续逐步进入芯片、光刻机、智能生态等产业。

所以长篇并不是永远只写考试，而是先把第一块计分板结算，再打开新的计分板。

## 7. 长线为什么还能继续

610章目录显示，后期能力规模虽然继续放大，但现实赛道也同步升级：项目、公司、利润、芯片工艺、半导体、光刻机、生态链等不断提供新的外部约束。

这形成一种**纵向扩张**：

> 学习效率 → 大学计算机能力 → 游戏/产品 → 公司 → 芯片/产业。

不是“这一章学习、下一章格斗、再下一章彩票”的横向模块巡演。

### 强样本编码

- `cumulative_progress_legibility`: 很高；
- `stage_gate_closure`: 很高；
- `progression_headroom`: 高；
- `module_demo_trap`: 低；
- `causal_attribution_clarity`: 高；
- `agency_share`: 中高；
- `promise_surface_alignment`: 高；
- `intermediate_proof_density`: 高。

正式升级：**extreme-verified #6**。

# 二、《超级全能学生》（紫函）：弱样本

## 1. 原生表现与观察窗口

番茄原生页本轮重新核验：

- 紫函版本；
- 已完结；
- 91.4万字；
- 455章；
- 当前未满1000人在读；
- 作品并非刚上线，观察窗口足够长。

原生来源：

- https://fanqienovel.com/keyword/7540438020344809472
- 第1章：https://fanqienovel.com/reader/7419913212067318808
- 第2章：https://fanqienovel.com/reader/7419913193226521624
- 第3章：https://fanqienovel.com/reader/7419913194270903320

## 2. 先修正旧判断：它并没有“标题骗人”

此前我们把它的问题粗略写成`promise coherence`差，这次需要修正。

它的书名就是《超级全能学生》，简介也明确承诺：

- 学习解题；
- 战斗形态；
- 体育能力；
- 超脑芯片带来的全能。

所以从`promise_surface_alignment`来说，它其实**相当诚实**：书名说全能，前期开篇确实一直展示全能。

不能因为它表现弱，就倒推成“承诺不一致”。

## 3. 第一章：人类利益并不弱

第一章的human stake其实相当完整：

- 主角见义勇为被刺；
- 父亲是出租车司机，为大学学费每天工作十多个小时；
- 主角原本长期班级吊车尾；
- 主角明确想到“考好大学、改善家庭”。

所以这本也不能被解释成“没有现实目标”。

真正的结构差异出现在能力展开方式。

## 4. 第一章能力一次性变成模块清单

超脑绑定后，很快同时列出：

- 超级管理员/联网；
- 运动神经复制，可以复制特种兵、运动员、厨师等专业能力；
- 逻辑运算；
- 伤口修复等前置效果。

第二章立即调用特种兵记忆解决混混；第三章又切回物理题，形成校内学习见证。

单看每一章，爽点都成立。

问题是它很容易进入一种结构：

> **这一章证明格斗模块，下一章证明学习模块，再下一章证明体育模块，再去证明财富模块。**

这就是新增：

- `module_demo_trap`：当能力由许多并列模块构成时，开篇是否退化成“逐项演示功能”，每次兑现很爽，却不能显著累加到同一条人生进度曲线。

## 5. 前20章：不是没兑现，而是兑现太横向

前20章目录：

- 第3章：物理解题；
- 第6～7章：计算/数学相关高阶能力；
- 第11章：《保送数学系博士》；
- 第14～15章：篮球；
- 第16～17章：律师/社会线；
- 第18～20章：彩票；
- 第21章：领奖；
- 第24章：买车。

这本的“事情多、兑现快”几乎没有争议。

但和《台式机》相比，差异变成：

> 《台式机》每一次胜利都让“255→985→大学→事业”这条人生进度更清楚；
>
> 《超级全能学生》更多是在横向证明“我还能做这个”。

因此新增另一个变量：

- `progress_topology`：进展是**纵向累计**，还是**横向模块巡演**。

## 6. 第一块计分板可能过早失去增长空间

第一章刚建立“吊车尾→好大学”的目标，第11章标题已经推进到“保送数学系博士”。

即使具体情节未必等于正式人生终局，这种标题级奖励仍会让原本最清楚的校园计分板极快接近天花板。

因此增加：

- `scoreboard_saturation_speed`：第一块计分板多快逼近上限；
- `progression_headroom`：在第一次大胜之后，读者还能否直观看到同一方向上剩下多少可追的成长空间。

## 7. 为什么这个弱样本特别重要

它至少拥有：

- 清楚家庭利益；
- 校园身份差距；
- 快能力兑现；
- 真实老师/同学见证；
- 书名与能力类型一致；
- 大量即时爽点。

所以它继续证明：

> **“计分板清楚 + 兑现快 + 外部见证 + 承诺一致”仍然不是充分条件。**

还必须看这些胜利是否能累加、是否过早打满第一块进度条、是否让读者追的是“人生变化”而不是“下一项功能演示”。

### 弱样本编码

- `human_stake_preload`: 高；
- `promise_surface_alignment`: 高（本轮修正旧判断）；
- `cumulative_progress_legibility`: 低/中；
- `module_demo_trap`: 高；
- `scoreboard_saturation_speed`: 过快；
- `progression_headroom`: 低于强对照；
- `objective_concentration`: 中低；
- `payoff_scene_density`: 不低；
- `causal_attribution_clarity`: 中高（能力来源倒并不模糊）。

正式升级：**extreme-verified #7**。

# 三、《我靠打爆学霸兑换黑科技》：长线强样本

## 1. 原生表现

番茄原生页本轮重新核验：

- 已完结；
- 455.4万字；
- 1883章目录；
- 当前约11万人在读量级；
- 2025年已完成长篇完结。

原生来源：

- https://fanqienovel.com/page/7250760921138596896
- https://fanqienovel.com/keyword/5538616
- 第1章：https://fanqienovel.com/reader/7250761233379525120
- 第3章：https://fanqienovel.com/reader/7250787480037917196
- 第19章：https://fanqienovel.com/reader/7252684905929736761

## 2. 第一章：系统出现以前，主角已经不是零agency

第一章把学校直接写成一个高度公开的竞技场：普通班、精英班、火箭班等分层，成绩就是人人看得懂的社会等级。

主角中考约620分，精英班通常要求约640分，他并非纯粹“系统来了才第一次学习”。开学前已经自己提前学高中数学，面对老师提问也有真实的基础能力。

随后同学因他的表现产生负面情绪，怨念值达到启动阈值，系统才正式开启。

这一点很关键：

> **现实行动先制造反馈，反馈再启动外挂。**

这比“绑定系统→系统发任务→主角开始做事”更接近SEED。

## 3. 核心资源循环极易看懂

作品最强的不是“怨念值这个词有趣”，而是资源循环几乎完全贴在现实冲突上：

> 超过学霸/让对手破防 → 产生怨念值 → 用怨念值换能力/道具 → 回到同一场学习/竞赛 → 取得更强结果 → 新对手/老师/同学继续产生反馈。

第3章的心算胶囊又没有无限白送：

- 需要100怨念值购买；
- 只持续约一小时；
- 可叠加但会增加身体能量消耗，存在虚脱风险。

因此新增：

- `resource_loop_visibility`：读者能否清楚看到“现实反馈如何变成资源、资源如何被花掉、花掉后如何回到现实得到下一次验证”。

对SEED来说，这比一个复杂的隐藏经验值算法重要得多。

## 4. 前20章：系统燃料与现实计分板完全耦合

目录高度集中：

- 第3章：心算胶囊；
- 第8章：双竞赛双奖；
- 第10章：追赶/竞争；
- 第15～20章：高考数学卷、赶超、选拔考、怪兽宋河。

第19章是真正的数学选拔考现场，不是旁白一句“他考试第一”。主角仍要把答案一步步写在试卷上，现实竞赛负责验证外挂效果。

约2万字节点大致已经进入第8～10章区域：核心循环不是只解释了一次，而是已经多次运行——学习/竞争产生情绪反馈，系统资源反过来帮助下一轮学习和竞争。

所以这本的`feedback_fuel_alignment`比单纯“完成任务得经验”更强：

> **真实剧情冲突本身就是系统的燃料来源。**

## 5. 长线：计分板可以换，但反馈拓扑没有断

455万字长线目录显示，作品后面会从：

- 校内成绩/竞赛；
- 数学、生物等学科竞争；
- 工程菌、抗生素、论文；
- 研究项目、公开测速、项目立项；
- 更大科研/产业与国家层技术竞争；

不断升级。

具体项目会换，但“公开竞争/研究成果→别人反应→新资源/新能力→更大公开竞争”的主循环一直有辨识度。

这是一种比单一计分板更长寿的结构：

> **表层计分板可以升级，底层反馈循环不变。**

## 6. 对SEED最直接的价值

如果SEED真的以“从真实反馈中学习”为独特机制，那么最值得借鉴的不是怨念设定，而是其**资源闭环可见性**：

- 现实中先发生一个失败/竞争/客户反应；
- 这个反馈必须是故事真正发生的，不是系统自己生成的训练数据；
- SEED从该反馈学到一个明确改进；
- 改进只服务当前问题；
- 马上回到现实同一指标重新验证；
- 新结果再制造下一轮反馈。

- `scoreboard_coupling`: 极高；
- `agency_before_cheat`: 中高；
- `cumulative_progress_legibility`: 高；

# 四、三本配对后的新结论：真正区分它们的是“进展拓扑”

以前我们问：

> 能力是不是太多？

现在这已经不够准确。

三本都可以拥有很多能力，但结构完全不同：

### A. 纵向累计型——《台式机》

> 255 → 模拟考上升 → 597 → 高考 → 名校 → 大学 → 游戏/公司 → 科技产业

新能力不断推动同一条人生阶梯向上。

### B. 横向模块巡演型——《超级全能学生》

> 格斗模块 → 学习模块 → 篮球模块 → 彩票模块 → 其他模块

每次都能爽，但读者更容易看到“又展示了一个功能”，而不是“主角在同一条人生曲线上走到了更高位置”。

### C. 反馈闭环型——《我靠打爆学霸》

> 现实竞争 → 对手反馈 → 系统燃料 → 能力 → 回到现实竞争 → 更强反馈

它既能纵向累计，又能让每一轮剧情自动生产下一轮成长资源。

因此新增总变量：

- `progress_topology`：一本书的进展主要是纵向累计、反馈闭环，还是横向模块巡演。

并补充四个子字段：

- `cumulative_progress_legibility`
- `module_demo_trap`
- `scoreboard_saturation_speed`
- `progression_headroom`
- `resource_loop_visibility`

# 五、对SEED的进一步约束

这一轮后，SEED如果继续，设计上应尽量满足：

## 1. 不做“模块解锁列表”

不能写成：

- 这次学会写代码；
- 下次解锁黑客；
- 再下次解锁投资；
- 然后突然会科研。

这很容易落入`module_demo_trap`。

## 2. 新能力必须由同一现实项目逼出来

更理想的是：

> 当前项目遇到一种新的真实失败 → 收集失败数据/用户反馈 → SEED只学会解决这一类失败所需的能力 → 同一项目复测 → 指标变好。

能力来源和应用目标因此天然耦合。

## 3. 第一块计分板不要十章打满

SEED第一阶段需要足够`progression_headroom`。

比如不能从“普通学生/普通程序员”十章内直接变成国家级AI首席专家。更合理的是：

> 基线失败率/收入/排名 → 小幅可验证改善 → 稀缺机会 → 第一真实客户/合同 → 产品可用 → 可复制增长。

每一层都能被外部世界看到，但仍给下一层留下空间。

## 4. 让成长资源的来源对读者可见

SEED内部可以复杂，但读者面对的循环必须简单：

> **哪里失败 → 收到了什么真实反馈 → 学会了什么 → 哪个现实指标改善。**

如果读者无法复述这四步，机制就容易再次变成“AI能力本身就是剧情”。
